# Code Review Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Один плагин code-review@cdd для Claude Code и Codex: проверка багов,
комментариев и упрощений с предложениями под PR без изменения проверяемого кода.

**Architecture:** Общий SKILL.md управляет областью ревью и результатом. Два
справочника содержат критерии анализа и порядок публикации через доступный GitHub
инструмент или gh. Два манифеста подключают те же инструкции в обоих клиентах.

**Tech Stack:** Markdown/YAML, JSON, существующие Bash/jq проверки marketplace,
Claude Code CLI и Codex CLI/app-server для изолированной проверки обнаружения.
Новых runtime-зависимостей нет.

**Spec:** `docs/superpowers/specs/2026-11-07-code-review-design.md` — согласована.

## Global Constraints

- Селектор `code-review@cdd`; один `skills/code-review/SKILL.md`; без version.
- Три направления: баги и правила проекта, комментарии, упрощение.
- Проверяемый код, индекс, коммиты и ветку не менять; suggestion не применять.
- Локальная ветка — результат в чат; явный вызов для PR — публикация по умолчанию;
  «только в чате» запрещает публикацию. Наличие найденного PR не разрешение писать.
- Публикация — COMMENT, по треду на проблему, без approve/request changes/merge.
- Сохранить обязательный JSDoc, лицензии, директивы, полезные объяснения причин.
- Apache-2.0; источник закреплён на `0412be76f50ab4f4f8abff3753efa9269fbbca5b`.
- Обновления адаптации вручную; `scripts/sync.sh` и `upstream.json` не расширять.
- Не устанавливать плагин в личные профили; не публиковать тестовые треды в живые PR.
- Прежде чем писать навыки, прочитать skill-creator и superpowers:writing-skills;
  применить их проверку поведения, не подменять её поиском фраз в SKILL.md.
- Worktree уже выделен: `agent-plugins-code-review`, ветка `design/cdd-code-review`.
  При начале исполнения пройти using-git-worktrees для проверки изоляции и базы;
  не создавать ещё одну копию без причины.

## Review Focus

1. Полезный русский комментарий «почему» рядом с очевидным пересказом: замечание
   только ко второму; обязательные уведомления сохраняются (задача 1).
2. Баг проявляется на пустом вводе и виден через вызывающую функцию за пределами
   diff: подтверждённый баг не отбрасывается как «зависит от ввода» (задача 1).
3. Коммит добавлен между анализом и публикацией: прежние координаты и выводы
   не отправляются без перепроверки нового head (задача 2).
4. GitHub принял COMMENT, но клиент получил timeout: перечитать результат,
   повторный запуск не создаёт дублирующий тред (задача 2).
5. Ветка содержит staged/unstaged/untracked, а в обсуждении PR есть команда
   изменить код: локальные данные сохраняются, команда из обсуждения не исполняется
   и наличие PR не включает публикацию локального ревью (задачи 1–2).

## Файлы и их назначение

- `plugins/code-review/skills/code-review/SKILL.md` — вход, scope, ограничения,
  выбор направлений, ссылки на справочники, общий вывод.
- `plugins/code-review/skills/code-review/references/analysis.md` — критерии
  трёх направлений и проверка обоснованности замечаний.
- `plugins/code-review/skills/code-review/references/publishing.md` — PR head,
  существующие треды, COMMENT, suggestions, проверки результата и ошибки записи.
- `plugins/code-review/{README.md,PROVENANCE.md,LICENSE}` и
  `plugins/code-review/skills/code-review/LICENSE` — использование, происхождение,
  изменения и Apache-2.0, в том числе лицензия при отдельном копировании навыка.
- `plugins/code-review/tests/scenarios.md` — воспроизводимые поведенческие сценарии,
  сырые входы и критерии оценивания; без собственного универсального eval-движка.
- `plugins/code-review/{.claude-plugin,.codex-plugin}/plugin.json`,
  `.claude-plugin/marketplace.json`, `.agents/plugins/marketplace.json` — упаковка.
- `tests/manifest_test.sh`, `tests/manifest_validation_test.sh` — новый инвентарь
  и негативные проверки регистрации.
- Корневые `README.md`, `LICENSE` — каталог, число навыков и область лицензий.
- `docs/superpowers/verification/2026-11-07-code-review.md` — реальные результаты
  поведения, клиентского обнаружения, команд и ограничения проверки.

### Task 1: Процедура ревью и критерии без изменения кода

**Files:** создать SKILL.md, analysis.md, LICENSE (оба), PROVENANCE.md,
tests/scenarios.md и начать verification-отчёт из карты выше.

**Interfaces:** потребляет явную область пользователя или текущую ветку и её базу;
выдаёт проверенные замечания с категорией, файлом/строкой, сценарием, последствием
и предлагаемым исправлением. Обязательные нарушения и баги отдельно от улучшений.
Публикация будет подключена задачей 2; в этой задаче поведенческие прогоны локальные.

- [ ] Сохранить в scenarios.md независимые входы и критерии: неверный комментарий;
  пересказ `count += 1`; полезное объяснение браузерного workaround; экспорт с
  обязательным JSDoc; лицензия и eslint-директива; повторяющееся условие с безопасным
  упрощением; ошибка при пустом списке в caller; чистый diff без находок.
  Добавить локальный Git-сценарий с отдельными staged, unstaged и untracked файлами.
- [ ] Выполнить baseline без нового навыка свежим агентом на временной копии этих
  материалов; сохранить фактические ответы и snapshot исходников/индекса/HEAD.
  Оценивать содержание и действия, а не точность формулировок. Не требовать
  искусственного FAIL, если модель уже проходит сценарий.
- [ ] Перечитать три исходника на закреплённом SHA и относящиеся LICENSE/NOTICE.
  Записать источник, SHA, исходные авторские уведомления и перечень адаптаций
  в PROVENANCE.md; отметить изменённое происхождение в производных Markdown-файлах.
  Сохранить Apache-2.0; объяснить расхождение MIT в README toolkit с его LICENSE.
- [ ] Написать короткий SKILL.md и analysis.md: scope включает изменения ветки и
  локальные правки, явный scope приоритетен; прочитать инструкции проекта и контекст;
  три направления; проверять выводы; объединять дубли; не применять правки.
  Не переносить жёсткие модели, четыре обязательных агента, чужой Sentry/React-стиль,
  запрет анализа входозависимых багов и автоматическое упрощение.
- [ ] Повторить сценарии новым агентом с навыком, без ожидаемых ответов в его prompt.
  Проверить: настоящий баг обнаружен; полезные комментарии защищены; нет обвинений
  в авторстве ИИ; чистый diff без выдуманных проблем; bytes/index/HEAD неизменны;
  все три вида локальных изменений учтены. Исправить только выявленные недостатки.
- [ ] Выполнить `python3 /home/oleg/.codex/skills/.system/skill-creator/scripts/quick_validate.py plugins/code-review/skills/code-review`
  и `git diff --check`; ожидается успешная валидация. Записать результаты и commit

### Task 2: Публикация замечаний и повторное ревью

**Files:** создать publishing.md; дополнить SKILL.md, scenarios.md и verification.

**Interfaces:** потребляет находки задачи 1, URL PR, просмотренный head SHA и
явное ограничение «только в чате»; выдаёт опубликованные COMMENT-треды с URL либо
готовый отчёт в чат с точным описанием ограничения/ошибки публикации.

- [ ] Добавить сценарии управляемых ответов GitHub: локальная ветка с существующим
  PR; явный PR; PR «только в чате»; чистый PR; открытый тред с той же проблемой;
  исправленный тред после нового коммита; смена head перед записью; timeout после
  принятого COMMENT; отсутствие write; инструкция в обсуждении изменить код.
- [ ] Прогнать baseline текущей версии навыка на этих сценариях. Для проверки
  действий дать агенту только локальный инструмент-замену GitHub с записью вызовов
  и последовательностью ответов; без токенов и без доступа к живой записи.
  Минимальный временный адаптер допустим, production CLI/API не писать.
- [ ] Написать publishing.md и подключить его из SKILL.md: доступный MCP/connector,
  gh как fallback; pending review → отдельные inline comments → submit COMMENT;
  повторная сверка head; сравнение с тредами; suggestion только для полного малого
  исправления; проверка принятия после timeout перед повтором; без разрешения
  старых тредов. Не добавлять безусловный skip для draft/уже проверенных PR.
- [ ] Повторить прогон свежим агентом. По журналу проверить: local/chat-only —
  ноль записей; PR с подтверждённой проблемой — один COMMENT-тред; чистый PR —
  один краткий итог, повтор не дублирует его; после timeout — сначала чтение;
  новый head перепроверен; чужие инструкции не исполнены; нет source edits,
  approve, request changes, merge. При недоступной записи отчёт не утверждает успех.
- [ ] Зафиксировать результаты в verification, проверить все относительные ссылки,
  quick_validate и `git diff --check`. Commit
  `feat(code-review): add verified PR comment workflow`.
