# Актуализация cdd-tasks — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Способ выполнения выбирает пользователь до реализации.

**Goal:** Привести cdd-tasks к согласованному процессу задач, релизов, разрешений и графа модулей.

**Architecture:** Сохранить один скилл и его справочник. Изменять SKILL.md, REFERENCE.md и README согласованно; проверять поведение существующим механизмом plugin eval, без новой системы автоматизации.

**Tech Stack:** Markdown, Bash, gh CLI, Claude plugin eval, Codex plugin marketplace.

**Spec:** `docs/superpowers/specs/2026-11-15-cdd-tasks-refresh-design.md` (подтверждена пользователем).

## Global Constraints

- Worktree: `/home/oleg/2026_H2/agent-plugins/.worktrees/cdd-tasks-refresh`, ветка `docs/cdd-tasks-refresh`.
- Не менять реальные задачи, поле «Трек», CI/CD, правила GitHub, приложение или граф модуля №3 в рамках этой доработки скилла.
- Merge — отдельное поручение. Разрешение на привязку не разрешает merge.
- Кэш вручную не редактировать. Установка обновления — после попадания изменений в источник.
- Пользовательские исключения сохранять как исключения, не выдавая их за общекомандную политику.
- До правки руководств прочитать writing-skills и test-driven-development. Перед каждой задачей сохранить baseline поведения, после правки повторить те же сценарии.
- Задачи последовательные: первые две изменяют одни SKILL.md/REFERENCE.md. Результаты eval хранить в игнорируемом `plugins/cdd-tasks/evals/results/`; не коммитить сырые диалоги, кэш или настройки аккаунтов.

## Review Focus

- Поздние merge/closed и ручной reopen: не отменять актуальный production-результат или ручное решение (Task 1).
- Health check без сохранённого production success: не объявлять Done и не запускать recovery на неподтверждённом deployment (Task 1).
- Разрешение bypass при изменившемся head или красном CI: разрешение не заменяет повторную проверку (Task 2).
- Родитель с завершёнными детьми из других модулей: наследование «Трека» не должно приписывать чужую историю новому модулю (Task 2).
- Новый вариант «Трека» ещё не создан CI: подготовленный PR не означает публикацию графа и не разрешает merge (Task 2).

## Протокол проверки поведения

Для каждого указанного ниже case выполнить команду до правки соответствующего руководства и после неё:

```bash
claude plugin eval plugins/cdd-tasks --case CASE --runs 3 --max-cost-usd 4 --no-publish --no-scaffold --trust-plugin
```

Заменить CASE конкретным именем из задачи. CLI проверен через `--help`: по умолчанию запускает варианты с плагином и без него. Prompts разрешают только `[Read, Glob, Grep, Skill]`; не добавлять Bash/Write/MCP, не включать real servers. Промпты задают разбор по материалам, без сети и реальных действий. Каждый прогон сохранять отдельно, фиксируя commit/состояние документов, полный ответ и оценки.

RED: в ответах старого скилла наблюдается конкретная ошибка или отсутствие необходимой процедуры; выписать её дословно. Успешный baseline не переименовывать в провал: уточнить, проверяет ли сценарий найденное расхождение. GREEN: после изменения все обязательные критерии соблюдены во всех трёх ответах; вручную проверить решения и команды, одного score недостаточно. Лимит, ошибка авторизации или сбой runner — незавершённая проверка, а не результат поведения.

Если CLI фактически не запускается, применить предусмотренные writing-skills свежие read-only субагенты: те же prompts, отдельно без скилла/со старым/с новым, по три независимых прогона. Записать причину замены runner и сохранить ответы. Новую eval-инфраструктуру не создавать.
