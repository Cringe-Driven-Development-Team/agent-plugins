# cdd-apidog: единый формат имени командного скилла

Дата: 2026-11-04. Статус: имя выбрано пользователем; спецификация ожидает согласования.

## Цель

Привести новый Apidog-плагин к формату `cdd-<область>` рядом с существующим
`cdd-tasks`. Пользователь выбрал `cdd-apidog`. Контекст проекта и правила работы
с Apidog остаются прежними.

## Подходы

1. **Выбран пользователем:** оставить `cdd-tasks`, переименовать новый
   `apidog-cdd` в `cdd-apidog`. Изменения входят в ещё открытый PR #26.
2. Формат `<область>-cdd`: сохранить `apidog-cdd`, переименовать уже используемый
   `cdd-tasks` в `tasks-cdd`. Отклонён в пользу изменения нового плагина.

## Объём

- Каталог плагина: `plugins/cdd-apidog/`; каталог скилла:
  `plugins/cdd-apidog/skills/cdd-apidog/`.
- Имя в `SKILL.md`, обоих манифестах и внутренних ссылках: `cdd-apidog`.
- Селектор установки: `cdd-apidog@cdd`; полное имя скилла:
  `cdd-apidog:cdd-apidog`.
- Обновить оба marketplace, README, списки и отрицательные сценарии существующих
  тестов упаковки. Закрепить в README формат для командных скиллов с контекстом CDD.
- Актуализировать проектную документацию. Завершённые отчёты о проверках и записи
  прежних команд сохранить как исторические факты с указанием нового имени;
  не представлять старые проверки как выполненные после переименования.
- Обновить заголовок и описание существующего PR #26 после реализации и проверок.

## Границы

Не переименовывать `cdd-tasks`, другие плагины или восемь официальных Apidog-скиллов.
Не добавлять alias старого имени: новый плагин ещё не влит и локально не установлен.
Не менять способы установки, scope, инструкции по API и поведение скилла.
Работать в текущей ветке `skill/apidog-cdd`; имя ветки и путь worktree не относятся
к публичному имени плагина и не требуют изменения. Слияние и установка не входят
в это переименование.

## Приёмка

Оба marketplace указывают на существующий новый каталог, оба манифеста и скилл
согласованы по имени. В активных файлах плагина, каталогах, README и тестах нет
старого селектора или путей. Исторические упоминания объяснены.

Запустить существующие `tests/manifest_test.sh`,
`tests/manifest_validation_test.sh`, валидатор скилла по новому пути,
`claude plugin validate plugins/cdd-apidog` и `git diff --check`.
Новых поведенческих тестов для механического переименования не требуется.

## Решения исполнителя

Точные формулировки README и PR, минимальные примечания к историческим документам.
Реализация начинается после согласования этой короткой спецификации.
