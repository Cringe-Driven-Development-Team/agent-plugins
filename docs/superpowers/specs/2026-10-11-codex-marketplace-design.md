# Маркетплейс CDD для Codex

Дата: 2026-10-11. Статус: на согласовании.

Репозиторий: `Cringe-Driven-Development-Team/claude-plugins`.
Основа: `origin/main`, коммит `b745231fc95307f63eeaa6fc5fa67ff3c113392c`.
Выбранный подход согласован пользователем: отдельный каталог Codex и явные
манифесты `.codex-plugin/plugin.json`, использующие существующие `skills/`.

## Цель и сценарий участника

Участник команды подключает репозиторий как маркетплейс `cdd` в Codex,
устанавливает нужные плагины и получает те же навыки, что доступны через
маркетплейс Claude Code. Ручные симлинки и повторная установка отдельных
навыков не нужны.

Подключение, установка, включение в проекте и обновление описаны в README.
Критерий успеха — обнаружение навыков самим Codex после установки, включая
доступ к их вложенным материалам. Успешного копирования файлов недостаточно.

## Состав и границы

Сохраняются четыре независимо устанавливаемых плагина:

| Плагин | Навыки | Число |
|---|---|---:|
| `pulumi` | `pulumi-best-practices`, `pulumi-component`, `pulumi-debug-failed-operation`, `provider-upgrade`, `pulumi-cli`, `pulumi-typescript` | 6 |
| `ansible` | `ansible-good-practices`, `ansible-org` | 2 |
| `selectel-ops` | `selectel-ops` | 1 |
| `cdd-tasks` | `cdd-tasks` | 1 |
| Всего | | 10 |

Входят каталог Codex, четыре манифеста, документация подключения и проверки
упаковки, установки и обновления. Тексты навыков, синхронизация апстримов и
лицензии продолжают использовать существующую структуру репозитория.

Не входят общий плагин `all-skills`, переход на переносимый корневой
`plugin.json`, новые навыки, MCP-серверы, хуки, публикация в публичном каталоге
OpenAI, автоматическая настройка других репозиториев и изменение личной
установки пользователя. Поведенческая адаптация текстов навыков к Codex —
отдельная задача; в этой доработке проверяется их упаковка и доступность.

## Структура

```text
.agents/plugins/marketplace.json          каталог Codex «cdd»
.claude-plugin/marketplace.json           существующий каталог Claude Code
plugins/<плагин>/
  .codex-plugin/plugin.json               явный манифест Codex
  .claude-plugin/plugin.json              существующий манифест Claude Code
  skills/<навык>/                         общие исходники навыка
  references/                            материалы в корне плагина, если есть
```

Каталог Codex указывает на корень каждого плагина `./plugins/<имя>`.
Устанавливается весь плагин: в частности, `plugins/ansible/references/*.adoc`
должны попасть в установленную копию вместе с навыками. Ссылки на каталоги
отдельных навыков вместо корня плагина не используются.

Файлы навыков не копируются в отдельное дерево Codex. Добавление навыка в
существующий `skills/` не требует перечислять его ещё раз в манифесте.

## Контракт каталога Codex

`.agents/plugins/marketplace.json` содержит:

- `name: "cdd"`;
- `interface.displayName: "Cringe Driven Development"`;
- четыре записи `plugins[]` с именами, совпадающими с каталогом Claude Code;
- источник каждой записи: `{"source":"local","path":"./plugins/<имя>"}`;
- `policy.installation: "AVAILABLE"` — участник выбирает нужные плагины;
- `policy.authentication: "ON_INSTALL"` и `category: "Productivity"`, как
  предусмотрено форматом каталога OpenAI. Здесь нет подключений к сервисам;
  настройка авторизации облаков не является частью установки навыка.

Пути разрешаются относительно корня маркетплейса. Они должны существовать,
начинаться с `./` и оставаться внутри репозитория. Для локальных записей не
используются удалённые источники или закрепление отдельной версии плагина.

## Контракт манифеста плагина

Каждый `plugins/<имя>/.codex-plugin/plugin.json` содержит `name`, `description`,
`author.name` и явное `skills: "./skills/"`. Имя и автор совпадают с
манифестом Claude Code; описание передаёт тот же состав и назначение плагина.

Путь `skills` разрешается от корня плагина, а не от `.codex-plugin/`.
Манифест не объявляет MCP, приложения или хуки. Существующие каталоги навыков
остаются настоящими каталогами, без внутренних симлинков для упаковки.

Поле `version` не задаётся в новых манифестах и записях каталога. Это сохраняет
принятый в репозитории подход к доставке изменений из Git без ручного повышения
версий. Допустимость отсутствия версии и фактическое обновление установленной
копии обязательны к проверке на целевом клиенте. Если клиент не поддерживает
этот контракт, реализацию нельзя считать принятой: результат проверки требует
корректировки спецификации, а не незаметного введения фиксированной версии.

## Документация подключения и обновления

README описывает маркетплейс для Claude Code и Codex. Разделы подключения
разделены по клиентам, общий каталог навыков сохраняется.

Для Codex приводится последовательность, которую при реализации необходимо
проверить на CLI:

```sh
codex plugin marketplace add Cringe-Driven-Development-Team/claude-plugins
codex plugin marketplace list
codex plugin list
codex plugin add pulumi@cdd
```

Аналогично доступны `ansible@cdd`, `selectel-ops@cdd` и `cdd-tasks@cdd`.
Участник устанавливает только нужные плагины.

README показывает включение установленного плагина в доверенном проекте:

```toml
# .codex/config.toml проекта
[plugins."pulumi@cdd"]
enabled = true
```

Документируется обновление каталога `codex plugin marketplace upgrade cdd`.
Отдельно объясняется обновление установленной копии: если целевому клиенту
после обновления каталога требуется повторный `codex plugin add <плагин>@cdd`,
этот шаг включается в инструкцию. Обновление каталога не объявляется гарантией
обновления установленного навыка без проверки содержимого.

Раздел добавления плагина перечисляет оба манифеста и оба каталога. Раздел
проверок содержит команду автоматической проверки и краткую процедуру проверки
в реальном Codex. Указывается фактически проверенная версия CLI; совместимость
со всеми ранними версиями и всеми интерфейсами Codex не обещается.

## Проверки и обработка ошибок

### Автоматические проверки структуры

Расширяется существующая проверка `tests/manifest_test.sh` либо добавляется
отдельная проверка Codex, включённая в документированный набор команд.
Зависимости остаются `bash` и `jq`; новый менеджер пакетов не нужен.

Проверяются валидность JSON, уникальность имён и совпадение набора плагинов
между каталогами двух клиентов. Для каждой записи проверяются обязательные
поля, корректный существующий путь, наличие манифеста Codex, совпадение имени
и автора и доступность объявленного `skills/` с `SKILL.md`.

Проверка не дублирует перечень навыков из таблицы в нескольких конфигурациях:
инвентарь берётся из существующих `plugins/*/skills/*/SKILL.md`. В отчёте
печатается фактическое число плагинов и навыков. Приёмка текущего изменения
ожидает 4 и 10 соответственно.

Отсутствующий плагин, повтор имени, неверный путь или недоступное дерево
навыков приводят к ненулевому коду с указанием проблемного файла или записи.
Проверяется, что такие ошибки действительно выявляются на временных копиях.
Существующая проверка запрета фиксированной версии Claude Code сохраняется;
для новых манифестов и каталога Codex проверяется тот же запрет.

### Проверка реального клиента

Базовый клиент — установленный `codex-cli 0.162.1`. Проверка выполняется в
отдельном временном профиле/окружении, без изменения личного конфига,
маркетплейсов, симлинков и установленных плагинов пользователя.

1. Добавить подготовленный маркетплейс из локального пути. Клиент обнаруживает
   каталог `.agents/plugins/marketplace.json` и видит ровно четыре плагина.
2. По отдельности установить все четыре плагина. Получить список навыков через
   штатный интерфейс Codex, например `skills/list` app-server.
3. Сверить имена: 6 навыков Pulumi, 2 Ansible, 1 Selectel и 1 CDD; всего 10.
   Путь каждого обнаруженного навыка должен вести в установленную копию
   соответствующего плагина, а не в глобальный симлинк или рабочее дерево.
4. Сверить содержимое навыков и вложенных ресурсов с источником. Обязательно
   проверить `ansible/references/coding_style.adoc`, справочник из
   `pulumi-cli/references/` и
   `selectel-ops/skills/selectel-ops/scripts/selectel.py`. Скрипт Selectel
   не выполняется и доступ к облакам не требуется.
5. Проверить доставку обновления через Git-источник во временном локальном
   Git-репозитории: новая ревизия меняет контрольный справочный файл; после
   документированных команд установленная копия содержит обновлённый файл.
   Изменённый материал не попадает в рабочий репозиторий задачи.
6. Сохранить в отчёте версию клиента, фактические числа, обнаруженные пути и
   команды обновления. Отсутствие навыка — провал приёмки даже при успешной
   установке плагина. Недоступность клиента — непроверенная приёмка, не успех.

При реализации выполняются также существующие проверки манифестов,
синхронизации и документации плагинов из README. Навыки из апстримов и их
ресурсы должны сохранить исходное содержимое.

## Критерии приёмки

1. Каталог Codex и четыре явных манифеста используют существующие файлы плагинов.
2. Codex обнаруживает все 10 навыков после установки четырёх плагинов.
3. Материалы в корне плагина и внутри навыков доступны из установленной копии.
4. Установка отдельных плагинов и обновление проверены и описаны в README.
5. Проверки выявляют несогласованные каталоги и сломанные пути; существующие
   проверки репозитория проходят.
6. Упаковка Claude Code, тексты навыков, ресурсы и лицензии сохранены.

- Справка `codex-cli 0.162.1`: `codex plugin --help`,
  `codex plugin add --help`, `codex plugin marketplace upgrade --help`.
  Она подтверждает установку через `plugin add`, в отличие от примеров
  документации, сосредоточенных на интерфейсе приложения.
- Существующая спецификация `docs/design.md`, структура `plugins/` и
  `tests/manifest_test.sh` в базовом коммите репозитория.
